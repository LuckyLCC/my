# 健身房会员管理系统 - 产品需求文档 (PRD)

## 1. 项目概述

### 1.1 项目背景
健身房会员管理系统是一个基于 Spring Boot + MyBatis + MySQL 开发的会员管理平台，旨在帮助健身房实现会员信息管理、卡种管理、员工提成计算、财务统计等核心业务功能。

### 1.2 项目目标
- 实现会员信息的全生命周期管理（开卡、续费、查询、更新）
- 支持多种卡种类型（月卡、季卡、年卡、次卡）的灵活配置
- 建立完善的员工提成计算体系
- 提供财务统计和报表导出功能
- 实现基于角色的权限管理系统
- 支持会员签到功能

### 1.3 技术架构
- **后端框架**: Spring Boot 4.0.0
- **持久层**: MyBatis 3.0.3
- **数据库**: MySQL 8.0+
- **认证**: JWT (JJWT 0.12.5)
- **Excel导出**: Apache POI 5.2.5
- **Java版本**: JDK 17

## 2. 用户角色

### 2.1 管理员 (ADMIN)
- 拥有所有系统权限
- 可管理员工账号（增删改查）
- 可管理提成规则（增删改查）
- 可管理卡种（增删改查）
- 可管理会员（增删改查）
- 可查看财务统计和导出报表

### 2.2 普通员工 (STAFF)
- 可查看会员信息（需有会员查看权限）
- 可创建会员（需有会员创建权限）
- 可更新会员信息（需有会员更新权限）
- 可删除会员（需有会员删除权限，默认无此权限）
- 可管理卡种（增删改查）
- 可进行会员签到操作
- 可查看财务统计（仅限自己相关的数据）

## 3. 功能需求

### 3.1 认证与授权模块

#### 3.1.1 用户登录
**功能描述**: 员工通过用户名和密码登录系统

**输入**:
- 用户名 (username)
- 密码 (password)

**输出**:
- JWT Token
- 员工ID
- 用户名
- 姓名
- 角色
- Token过期时间（30分钟）

**业务规则**:
- 用户名和密码不能为空
- 密码验证通过后生成JWT Token
- Token存储在数据库Session表中，用于双重验证
- Token有效期为30分钟
- 每次请求自动延长Token过期时间

#### 3.1.2 用户登出
**功能描述**: 用户主动登出，清除Session

**业务规则**:
- 删除数据库中的Session记录
- Token立即失效

#### 3.1.3 权限控制
**功能描述**: 基于角色和细粒度权限的访问控制

**权限类型**:
- 角色权限：ADMIN/STAFF
- 细粒度权限：
  - 会员创建权限 (member_create)
  - 会员查看权限 (member_read)
  - 会员更新权限 (member_update)
  - 会员删除权限 (member_delete)

**业务规则**:
- ADMIN角色默认拥有所有权限
- STAFF角色权限由管理员配置
- 接口级权限校验通过拦截器实现

### 3.2 员工管理模块

#### 3.2.1 员工列表查询
**功能描述**: 查询所有员工信息

**输出**:
- 员工ID
- 用户名
- 姓名
- 手机号
- 角色
- 状态（启用/禁用）
- 各项权限标识

**权限要求**: 仅管理员可访问

#### 3.2.2 员工详情查询
**功能描述**: 根据ID查询单个员工详细信息

**权限要求**: 仅管理员可访问

#### 3.2.3 创建员工
**功能描述**: 创建新员工账号

**输入**:
- 用户名（必填，唯一）
- 密码（必填）
- 姓名（必填）
- 手机号（可选）
- 角色（ADMIN/STAFF，默认STAFF）
- 状态（1-启用，0-禁用，默认1）
- 各项权限标识（1-有权限，0-无权限）

**业务规则**:
- 用户名必须唯一
- 密码不能为空
- ADMIN角色自动拥有所有权限

**权限要求**: 仅管理员可操作

#### 3.2.4 更新员工
**功能描述**: 更新员工信息

**输入**: 同创建员工，包含员工ID

**业务规则**:
- 不能修改自己的角色（防止权限丢失）
- 用户名唯一性校验

**权限要求**: 仅管理员可操作

#### 3.2.5 删除员工
**功能描述**: 删除员工账号

**业务规则**:
- 不能删除自己
- 检查员工是否有关联的会员记录

**权限要求**: 仅管理员可操作

### 3.3 会员管理模块

#### 3.3.1 会员列表查询
**功能描述**: 查询会员列表，支持多条件筛选

**输入参数**:
- name: 会员姓名（可选）
- phone: 手机号（可选）
- isExpired: 过期状态（0-未过期，1-已过期，可选）

**输出**:
- 会员ID
- 姓名
- 性别
- 手机号
- 身份证号
- 卡种信息
- 开始日期
- 到期日期
- 剩余次数（次卡）
- 是否过期
- 首次开卡员工
- 最新续卡员工
- 最近签到时间
- 超过7天未签到标识

**权限要求**: 需要会员查看权限

#### 3.3.2 会员详情查询
**功能描述**: 根据ID查询会员详细信息

**输出**: 包含会员所有信息及关联的卡种、员工信息

**权限要求**: 需要会员查看权限

#### 3.3.3 创建会员（开卡）
**功能描述**: 为新会员办理开卡业务

**输入**:
- 姓名（必填）
- 性别（可选）
- 手机号（必填）
- 身份证号（可选）
- 卡种ID（必填）
- 开始日期（必填）
- 业绩归属员工ID（必填）

**业务规则**:
1. 根据卡种类型自动计算到期日期：
   - 月卡/季卡：按月累加（如：1个月、3个月、6个月）
   - 年卡：按年累加（如：1年）
   - 次卡：默认1年有效期，记录剩余次数
2. 根据提成规则计算提成金额：
   - 查询该卡种的新开卡提成规则
   - 优先使用固定金额，否则使用比例计算（金额 × 比例%）
3. 创建会员记录
4. 创建交易记录（记录交易金额、提成金额、业绩归属员工）
5. 记录首次开卡员工ID

**权限要求**: 需要会员创建权限

#### 3.3.4 更新会员
**功能描述**: 更新会员基本信息

**输入**: 会员ID及要更新的字段

**业务规则**:
- 不能修改交易相关字段（如首次开卡人、最新续卡人）
- 更新卡种时需重新计算到期日期

**权限要求**: 需要会员更新权限

#### 3.3.5 删除会员
**功能描述**: 删除会员记录

**业务规则**:
- 检查是否有关联的交易记录
- 检查是否有关联的签到记录

**权限要求**: 需要会员删除权限（默认STAFF无此权限）

#### 3.3.6 会员续费
**功能描述**: 为现有会员办理续费业务

**输入**:
- 会员ID（必填）
- 卡种ID（必填，可以是新卡种）
- 续费日期（必填）
- 业绩归属员工ID（必填）

**业务规则**:
1. 判断原卡是否过期：
   - 未过期：从原到期日延长
   - 已过期：从续费日期开始计算
2. 根据新卡种类型计算新的到期日期
3. 根据提成规则计算续费提成：
   - 查询该卡种的续费提成规则
   - 优先使用固定金额，否则使用比例计算
4. 更新会员到期日期和剩余次数
5. 更新最新续卡员工ID
6. 创建交易记录

**权限要求**: 需要会员更新权限

#### 3.3.7 续费历史查询
**功能描述**: 查询会员的续费历史记录

**输出**: 该会员的所有交易记录（包含开卡和续费）

### 3.4 卡种管理模块

#### 3.4.1 卡种列表查询
**功能描述**: 查询所有启用的卡种

**输出**:
- 卡种ID
- 卡种名称
- 类型（MONTH-月卡，QUARTER-季卡，YEAR-年卡，TIMES-次卡）
- 时长（月/年/次数）
- 价格
- 状态（1-启用，0-禁用）

#### 3.4.2 卡种详情查询
**功能描述**: 根据ID查询卡种详细信息

#### 3.4.3 创建卡种
**功能描述**: 创建新的卡种

**输入**:
- 卡种名称（必填）
- 类型（必填，MONTH/QUARTER/YEAR/TIMES）
- 时长（必填，月/年/次数）
- 价格（必填）
- 状态（默认1-启用）

**业务规则**:
- 卡种名称不能为空
- 价格必须大于0

#### 3.4.4 更新卡种
**功能描述**: 更新卡种信息

**业务规则**:
- 如果卡种已被会员使用，需谨慎修改价格和时长

#### 3.4.5 删除卡种
**功能描述**: 删除卡种

**业务规则**:
- 检查是否有会员使用该卡种
- 检查是否有提成规则关联该卡种

#### 3.4.6 查询所有卡种（含禁用）
**功能描述**: 查询所有卡种，包括已禁用的，用于后台管理

**权限要求**: 通常需要管理员权限

### 3.5 提成规则管理模块

#### 3.5.1 提成规则列表查询
**功能描述**: 查询所有提成规则

**输出**:
- 规则ID
- 卡种ID
- 卡种名称
- 交易类型（NEW-新开卡，RENEW-续费）
- 提成比例（%）
- 固定金额

**业务规则**:
- 每个卡种的每种交易类型只能有一条规则
- 提成比例和固定金额二选一

#### 3.5.2 提成规则详情查询
**功能描述**: 根据ID查询提成规则详细信息

#### 3.5.3 创建提成规则
**功能描述**: 创建新的提成规则

**输入**:
- 卡种ID（必填）
- 交易类型（必填，NEW/RENEW）
- 提成比例（可选，百分比）
- 固定金额（可选）

**业务规则**:
- 同一卡种的同一交易类型不能重复
- 提成比例和固定金额至少填写一个
- 如果填写了固定金额，优先使用固定金额

**权限要求**: 仅管理员可操作

#### 3.5.4 更新提成规则
**功能描述**: 更新提成规则

**业务规则**: 同创建规则

**权限要求**: 仅管理员可操作

#### 3.5.5 删除提成规则
**功能描述**: 删除提成规则

**权限要求**: 仅管理员可操作

### 3.6 会员签到模块

#### 3.6.1 会员签到
**功能描述**: 记录会员到店签到

**输入**:
- 会员ID（必填）

**业务规则**:

4. 如果是次卡，检查剩余次数是否大于0
5. 记录签到时间、日期、操作员工
6. 如果是次卡，扣减剩余次数

**输出**: 签到记录信息

**功能描述**: 查询会员的签到历史记录

**输入**: 会员ID

#### 3.6.3 检查今日是否已签到

**输入**: 会员ID

**输出**: 布尔值（true-已签到，false-未签到）

- 记录执行日志

## 4. 非功能需求

### 4.1 性能需求
- 系统响应时间：普通查询接口响应时间 < 500ms

- 数据库查询优化：关键查询字段建立索引

- 密码加密存储（建议使用BCrypt）
- JWT Token签名验证
- 接口权限校验
- SQL注入防护（使用MyBatis参数化查询）
- XSS攻击防护
- CORS跨域配置

### 4.3 可用性需求
- 系统可用性：99%以上
- 数据备份：定期备份数据库
- 异常处理：全局异常处理器统一处理异常

### 4.4 可维护性需求
- 代码规范：遵循Java编码规范
- 日志记录：关键操作记录日志
- 接口文档：提供完整的API文档

## 5. 数据模型

### 5.1 核心实体

#### 5.1.1 员工 (Employee)
- id: 主键
- username: 用户名（唯一）
- password: 密码
- name: 姓名
- phone: 手机号
- role: 角色（ADMIN/STAFF）
- status: 状态（1-启用，0-禁用）
- member_create: 会员创建权限
- member_read: 会员查看权限
- member_update: 会员更新权限
- member_delete: 会员删除权限
- created_at: 创建时间
- updated_at: 更新时间

#### 5.1.2 用户会话 (UserSession)
- id: 主键
- employee_id: 员工ID（外键）
- token: JWT Token（唯一）
- expires_at: 过期时间
- created_at: 创建时间

#### 5.1.3 卡种 (CardType)
- id: 主键
- name: 卡种名称
- type: 类型（MONTH/QUARTER/YEAR/TIMES）
- duration: 时长（月/年/次数）
- price: 价格
- status: 状态（1-启用，0-禁用）
- created_at: 创建时间
- updated_at: 更新时间

#### 5.1.4 会员 (Member)
- id: 主键
- name: 会员姓名
- gender: 性别
- phone: 手机号
- id_card: 身份证号
- card_type_id: 卡种ID（外键）
- start_date: 开始日期
- expire_date: 到期日期
- remaining_times: 剩余次数（次卡使用）
- is_expired: 是否过期（1-是，0-否）
- first_employee_id: 首次开卡员工ID（外键）
- last_employee_id: 最新续卡员工ID（外键）
- status: 状态（1-正常，0-注销）
- created_at: 创建时间
- updated_at: 更新时间

#### 5.1.5 提成规则 (CommissionRule)
- id: 主键
- card_type_id: 卡种ID（外键）
- transaction_type: 交易类型（NEW/RENEW）
- commission_rate: 提成比例（%）
- fixed_amount: 固定提成金额
- created_at: 创建时间
- updated_at: 更新时间

#### 5.1.6 交易记录 (TransactionRecord)
- id: 主键
- member_id: 会员ID（外键）
- card_type_id: 卡种ID（外键）
- transaction_type: 交易类型（NEW/RENEW）
- amount: 交易金额
- commission_amount: 提成金额
- employee_id: 业绩归属员工ID（外键）
- transaction_date: 交易日期
- remark: 备注
- created_at: 创建时间

#### 5.1.7 会员签到 (MemberCheckin)
- id: 主键
- member_id: 会员ID（外键）
- checkin_date: 签到日期
- checkin_time: 签到时间
- employee_id: 签到操作员工ID（外键）
- remark: 备注
- created_at: 创建时间

### 5.2 数据关系
- 员工 1:N 会员（首次开卡人/最新续卡人）
- 员工 1:N 交易记录（业绩归属）
- 员工 1:N 会员签到（操作员工）
- 卡种 1:N 会员
- 卡种 1:N 提成规则
- 卡种 1:N 交易记录
- 会员 1:N 交易记录
- 会员 1:N 会员签到

## 6. 业务流程

### 6.1 开卡流程
```
1. 员工选择会员信息（姓名、手机号等）
2. 选择卡种
3. 系统自动计算到期日期（根据卡种类型和时长）
4. 选择业绩归属员工
5. 系统根据提成规则计算提成金额
6. 创建会员记录
7. 创建交易记录（记录交易金额、提成金额、业绩归属）
8. 记录首次开卡员工
```

### 6.2 续费流程
```
1. 选择要续费的会员
2. 选择新卡种（可以是原卡种或新卡种）
3. 系统判断原卡是否过期：
   - 未过期：从原到期日延长
   - 已过期：从续费日期开始计算
4. 系统根据新卡种计算新的到期日期
5. 选择业绩归属员工
6. 系统根据提成规则计算续费提成
7. 更新会员到期日期和剩余次数
8. 更新最新续卡员工ID
9. 创建交易记录
```

### 6.3 签到流程
```
1. 输入会员手机号或选择会员
2. 系统检查会员是否存在
3. 系统检查会员卡是否过期
4. 系统检查今天是否已签到
5. 如果是次卡，检查剩余次数
6. 记录签到信息（时间、日期、操作员工）
7. 如果是次卡，扣减剩余次数
```

### 6.4 提成计算流程
```
1. 根据卡种ID和交易类型（NEW/RENEW）查询提成规则
2. 如果规则存在固定金额，使用固定金额
3. 否则使用比例计算：交易金额 × 提成比例%
4. 将提成金额记录到交易记录中
```

- 卡种不存在

- 提成规则不存在
- 会员已过期
