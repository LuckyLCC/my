## 系统概述

本系统是一个健身房会员管理后台系统，提供会员管理、卡种管理、员工管理、财务统计等功能。

**技术栈：**
- 前端：Vue 3 + Element Plus（单页面应用）
- 后端：Spring Boot + MyBatis
- 数据库：MySQL

**权限说明：**
- 所有接口（除登录外）需要 Bearer Token 认证
- 员工管理和提成规则管理需要 ADMIN 角色权限

## 认证授权模块

### 1. 用户登录

**页面交互功能：**
- 显示登录对话框（系统启动时自动弹出）
- 输入用户名和密码
- 点击"登录"按钮提交
- 登录成功后自动关闭对话框，显示用户信息

**后端 API 接口：**
- `POST /api/auth/login`
- 请求体：`{ "username": "admin", "password": "admin123" }`
- 响应：`{ "code": 200, "message": "success", "data": { "token": "...", "username": "...", "name": "...", "role": "...", "employeeId": ... } }`

**正常流程（Happy Path）：**
1. 用户输入正确的用户名和密码
2. 前端发送 POST 请求到 `/api/auth/login`
3. 后端验证用户名密码，生成 Token
4. 返回 Token 和用户信息
5. 前端保存 Token 到 localStorage
6. 更新用户状态，关闭登录对话框
7. 自动加载卡种列表和员工列表

**异常流程：**
- **用户名或密码错误**：返回 `{ "code": 500, "message": "用户名或密码错误" }`，前端显示错误提示
- **网络错误**：前端显示网络错误提示
- **服务器错误**：返回 500 状态码，前端显示"系统错误，请联系管理员"

### 2. 用户登出

**页面交互功能：**
- 点击右上角"退出"按钮
- 清除本地 Token
- 清空用户信息
- 显示"已退出"提示

**后端 API 接口：**
- `POST /api/auth/logout`
- 请求头：`Authorization: Bearer {token}`
- 响应：`{ "code": 200, "message": "退出成功" }`

**正常流程：**
1. 用户点击退出按钮
2. 前端发送 POST 请求到 `/api/auth/logout`（带 Token）
3. 后端清除服务端 Session
4. 前端清除 localStorage 中的 Token
5. 重置用户状态
6. 显示"已退出"提示

**异常流程：**
- **Token 已过期**：返回 401，前端自动清除 Token 并提示重新登录
- **网络错误**：前端仍会清除本地 Token，确保用户状态正确

## 会员管理模块

### 1. 会员列表查询

**页面交互功能：**
- 显示会员列表表格
- 支持按姓名、手机号、是否过期筛选
- 点击"刷新"按钮重新加载数据
- 显示会员详细信息（姓名、性别、手机号、身份证、卡种、到期日期等）

**后端 API 接口：**
- `GET /api/members?name={name}&phone={phone}&isExpired={0|1}`
- 请求头：`Authorization: Bearer {token}`
- 响应：`{ "code": 200, "data": [会员对象数组] }`

**正常流程：**
1. 页面加载时自动调用接口获取会员列表
2. 用户输入筛选条件，点击刷新
3. 后端返回符合条件的会员列表
4. 前端渲染表格数据

**异常流程：**
- **未登录**：返回 401，前端显示"未登录：请先登录后再加载数据"，并弹出登录对话框
- **Token 过期**：返回 401，前端自动弹出登录对话框
- **服务器错误**：返回 500，前端显示错误信息

### 2. 新增会员（开卡）

**页面交互功能：**
- 点击"新增"按钮打开新增对话框
- 填写会员信息：姓名、性别、手机号、身份证、卡种、开始日期、剩余次数（次卡）、员工归属
- 选择次卡时自动填充剩余次数字段
- 点击"保存"提交

**后端 API 接口：**
- `POST /api/members`
- 请求头：`Authorization: Bearer {token}`
- 请求体：`{ "name": "...", "gender": "男", "phone": "...", "idCard": "...", "cardTypeId": 1, "startDate": "2024-01-01", "remainingTimes": 10, "employeeId": 1 }`
- 响应：`{ "code": 200, "message": "开卡成功", "data": {会员对象} }`

**正常流程：**
1. 用户点击新增按钮
2. 打开对话框，自动加载卡种列表和员工列表
3. 用户填写表单信息
4. 选择次卡时，自动填充剩余次数
5. 点击保存，前端发送 POST 请求
6. 后端创建会员记录，计算到期日期，创建交易记录
7. 返回成功信息
8. 前端关闭对话框，刷新列表，显示"新增成功"提示

**异常流程：**
- **未登录**：返回 401，提示重新登录
- **参数校验失败**：返回 400，显示具体字段错误信息
- **卡种不存在**：返回 500，显示"卡种不存在"
- **员工不存在**：返回 500，显示"员工不存在"
- **手机号重复**：返回 500，显示相应错误信息

### 3. 编辑会员

**页面交互功能：**
- 点击表格中某行的"编辑"按钮
- 打开编辑对话框，预填充会员信息
- 修改基本信息（姓名、性别、手机号、身份证）
- 点击"保存"提交

**后端 API 接口：**
- `PUT /api/members/{id}`
- 请求头：`Authorization: Bearer {token}`
- 请求体：`{ "name": "...", "gender": "男", "phone": "...", "idCard": "..." }`
- 响应：`{ "code": 200, "message": "更新成功", "data": {会员对象} }`

**正常流程：**
1. 用户点击编辑按钮
2. 打开对话框，预填充当前会员信息
3. 用户修改信息
4. 点击保存，发送 PUT 请求
5. 后端更新会员基本信息
6. 返回成功信息
7. 前端关闭对话框，刷新列表，显示"更新成功"提示

**异常流程：**
- **未登录**：返回 401
- **会员不存在**：返回 500，显示"会员不存在"
- **参数校验失败**：返回 400

### 4. 删除会员

**页面交互功能：**
- 点击表格中某行的"删除"按钮
- 弹出确认对话框
- 确认后执行删除

**后端 API 接口：**
- `DELETE /api/members/{id}`
- 请求头：`Authorization: Bearer {token}`
- 响应：`{ "code": 200, "message": "删除成功" }`

**正常流程：**
1. 用户点击删除按钮
2. 弹出确认对话框
3. 用户确认删除
4. 发送 DELETE 请求
5. 后端删除会员记录
6. 返回成功信息
7. 前端刷新列表，显示"删除成功"提示

**异常流程：**
- **未登录**：返回 401
- **会员不存在**：返回 500，显示"会员不存在"
- **有关联数据**：返回 500，显示相应错误信息

### 5. 会员签到

**页面交互功能：**
- 点击表格中某行的"签到"按钮
- 立即执行签到操作
- 显示签到结果提示

**后端 API 接口：**
- `POST /api/members/{memberId}/checkin?remark={备注}`
- 请求头：`Authorization: Bearer {token}`
- 响应：`{ "code": 200, "message": "签到成功", "data": {签到记录} }`

**正常流程：**
1. 用户点击签到按钮
2. 发送 POST 请求（自动带上当前登录员工ID）
3. 后端记录签到信息，更新会员最近签到时间
4. 如果是次卡，自动扣减剩余次数
5. 返回成功信息
6. 前端刷新列表，显示"签到成功"提示

**异常流程：**
- **未登录**：返回 401
- **会员不存在**：返回 500，显示"会员不存在"
- **次卡次数不足**：返回 500，显示"剩余次数不足"
- **卡已过期**：返回 500，显示"会员卡已过期"

### 6. 查看签到历史

**页面交互功能：**
- 点击表格中某行的"签到记录"按钮
- 打开对话框显示该会员的所有签到记录
- 显示签到日期、签到时间、操作员工、备注

**后端 API 接口：**
- `GET /api/members/{memberId}/checkins`
- 请求头：`Authorization: Bearer {token}`
- 响应：`{ "code": 200, "data": [签到记录数组] }`

**正常流程：**
1. 用户点击签到记录按钮
2. 发送 GET 请求
3. 后端返回该会员的签到历史
4. 前端在对话框中显示表格

**异常流程：**
- **未登录**：返回 401
- **会员不存在**：返回 500

### 7. 会员续卡

**页面交互功能：**
- 点击表格中某行的"续卡"按钮
- 打开续卡对话框
- 选择卡种、续卡日期、操作员工、备注
- 点击"确认续卡"提交

**后端 API 接口：**
- `POST /api/members/renew`
- 请求头：`Authorization: Bearer {token}`
- 请求体：`{ "memberId": 1, "cardTypeId": 2, "renewDate": "2024-02-01", "employeeId": 1, "remark": "..." }`

**正常流程：**
1. 用户点击续卡按钮
2. 打开对话框，自动加载卡种列表和员工列表
3. 用户选择卡种、日期等信息
4. 点击确认续卡
5. 后端计算新的到期日期，创建交易记录，计算提成
6. 如果是次卡，累加剩余次数
7. 返回成功信息
8. 前端关闭对话框，刷新列表，显示"续费成功"提示

**异常流程：**
- **未登录**：返回 401
- **会员不存在**：返回 500，显示"会员不存在"
- **卡种不存在**：返回 500，显示"卡种不存在"
- **参数不完整**：前端验证，显示"请填写完整信息"

### 8. 查看续卡历史

**页面交互功能：**
- 点击表格中某行的"续卡历史"按钮
- 打开对话框显示该会员的所有续卡记录
- 显示卡种、金额、续卡日期、操作员工、备注

**后端 API 接口：**
- `GET /api/members/{id}/renew-history`
- 请求头：`Authorization: Bearer {token}`
- 响应：`{ "code": 200, "data": [交易记录数组] }`

**正常流程：**
1. 用户点击续卡历史按钮
2. 发送 GET 请求
3. 后端返回该会员的续卡历史（交易类型为 RENEW 的记录）
4. 前端在对话框中显示表格

**异常流程：**
- **未登录**：返回 401

## 财务管理模块

### 1. 开卡统计

**页面交互功能：**
- 显示月份选择器（默认当前月）
- 显示汇总信息：月份、总开卡数量、总开卡金额、总提成金额
- 显示员工统计表格：员工ID、员工姓名、月份、开卡数量、开卡金额、提成金额
- 点击"开卡明细"列可查看详细记录

**后端 API 接口：**
- `GET /api/financial/card-summary?month=2024-01`
- 请求头：`Authorization: Bearer {token}`
- 响应：`{ "code": 200, "data": { "month": "2024-01", "totalCardAmount": 10000.00, "totalCardCount": 20, "employeeStats": [员工统计数组，每个包含 cardMembers 明细] } }`

**正常流程：**
1. 用户选择月份（默认当前月）
2. 点击刷新或自动加载
3. 后端统计该月所有员工的开卡情况
4. 返回汇总信息和员工统计
5. 前端显示汇总卡片和统计表格
6. 点击开卡明细，显示对话框展示详细记录

**异常流程：**
- **未登录**：返回 401
- **月份格式错误**：返回 500
- **无数据**：返回空数组，前端显示空表格

### 2. 交易明细

**后端 API 接口：**
- `GET /api/financial/transactions?employeeId={id}&month=2024-01&transactionType=NEW`
- 请求头：`Authorization: Bearer {token}`
- 响应：`{ "code": 200, "data": [交易记录数组] }`

**正常流程：**
1. 用户设置筛选条件
2. 点击刷新

## 通用异常处理

### 前端异常处理

1. **401 未授权**：
   - 自动弹出登录对话框
   - 显示"登录已过期，请重新登录"提示
   - 清除本地 Token

2. **403 权限不足**：
   - 显示"权限不足（需要管理员权限）"错误提示

3. **网络错误**：
   - 显示网络错误提示
   - 在列表页面显示错误文本

4. **服务器错误（500）**：
   - 显示服务器返回的错误信息
   - 如果无具体信息，显示"系统错误，请联系管理员"

### 后端异常处理

1. **参数校验失败（400）**：
   - 返回字段级别的错误信息
   - 格式：`{ "code": 400, "message": "参数校验失败", "data": { "fieldName": "错误信息" } }`

2. **未授权（401）**：
   - AuthInterceptor 拦截，返回 `{ "code": 401, "message": "未登录或登录已过期" }`

3. **权限不足（403）**：
   - AdminInterceptor 拦截，返回 `{ "code": 403, "message": "权限不足，仅管理员可访问" }`

4. **服务器错误（500）**：
   - GlobalExceptionHandler 统一处理
   - 返回业务错误信息或"系统错误，请联系管理员"

## 数据流转说明

### Token 管理

1. **登录时**：后端生成 Token，前端保存到 localStorage
2. **每次请求**：前端从 localStorage 读取 Token，添加到请求头 `Authorization: Bearer {token}`
3. **Token 验证**：AuthInterceptor 验证 Token 有效性，并刷新过期时间
4. **登出时**：前端清除 localStorage，后端清除服务端 Session

### 权限控制流程

1. **公开接口**：`/api/auth/login`（无需认证）
2. **认证接口**：所有 `/api/**` 接口（除登录外）需要 Token
3. **管理员接口**：`/api/employees/**` 和 `/api/commission-rules/**` 需要 ADMIN 角色

### 业务逻辑说明

1. **开卡流程**：
   - 创建会员记录
   - 根据卡种类型计算到期日期（月卡/季卡/年卡）或设置剩余次数（次卡）
   - 创建交易记录（类型：NEW）
   - 计算并记录提成

2. **续卡流程**：
   - 更新会员到期日期或累加剩余次数
   - 创建交易记录（类型：RENEW）
   - 计算并记录提成

3. **签到流程**：
   - 记录签到信息
   - 更新会员最近签到时间
   - 如果是次卡，扣减剩余次数

4. **过期检测**：
   - 系统定时任务每天凌晨1点自动检测并标记过期会员
